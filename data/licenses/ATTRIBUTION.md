# Corpus attribution and source distinctions

Documentation and generated API docstrings: Streamlit documentation contributors, https://github.com/streamlit/docs/tree/7a0a34742a9fe4a879fe3641f83b8136bc5448d7. Retained text is extracted from Markdown or generated docstring HTML; presentation components/frontmatter are removed, and API sections are reformatted. See docs-LICENSE.txt.

Contributor guide and bug template: Streamlit contributors, https://github.com/streamlit/streamlit/tree/4278206f51bde8026a20c7d91c4ef473fece6c69. See streamlit-LICENSE.txt and streamlit-NOTICES.txt. No upstream Python/JavaScript is executed.

Public GitHub issues: body excerpts supplied by the respective issue contributors, linked individually in sources.json. Issue text is attributed through its canonical GitHub URL and remains the content of its contributors; the repository Apache license is not asserted to relicense every issue submission. Profile/author fields, comments and attachments are excluded. Template checklists, obvious emails, credentials and @mentions are removed. Reports and issue state are evidence of what was reported at snapshot time, not an official diagnosis, exhaustive issue search, or proof that closed means fixed.

The corpus is a bounded educational snapshot, not an endorsement or an official Streamlit support service. Source records preserve URLs, commits where applicable, timestamps, version scope, and raw hashes. Source code snippets are retrieved as text only.
